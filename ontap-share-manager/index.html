Create a share and give a group access

  1. In Folders, pick the SVM and volume, then New Group Folder
  2. Pick the security group from Active Directory. Its members appear in a table
  3. Tick Full, Modify or Read for each person, or tick a column for everyone
  4. Create folder + share + permissions. The folder, the NTFS permissions and the Share are made together, and Everyone is removed

Migrate a Windows file server to ONTAP

  1. In Migration, type the server name and press Scan source. Its shares are listed and measured
  2. Add whole share or Choose folders..., then pick the destination volume and names
  3. Check the plan flags names that already exist and long paths
  4. Start migration copies data, NTFS permissions, owner and quotas, checks every folder file by file, then creates its Share

Find out who deleted a file

  1. In Share Auditing, press + Watch a folder once. ONTAP auditing is switched on for you
  2. Pick Today, 7 days or 30 days and choose Deleted, or search for the file
  3. Each line shows the user, the time, the file and the PC it came from
  4. Need it back? Restore brings an older version next to the original, without overwriting anything

Questions admins ask

Does it install anything on our NetApp or domain controllers?

No. It runs on the admin's Windows PC and uses the ONTAP REST API and a read-only AD account.

Which ONTAP versions are supported?

ONTAP 9.11.1 or later with SMB, NTFS volumes and an SVM joined to Active Directory.

Is migration really one click?

You scan the Windows file server and check the plan first. After that, Start migration copies every folder with its NTFS permissions and checks each one.

Can it tell me who deleted a file on a share?

Yes. Share Auditing uses ONTAP's own audit log to show deletes, renames, moves, changes and refused delete attempts, with the user and the PC.

Who controls what each admin can do?

Your ONTAP roles. The app does only what the signed-in NetApp account is allowed to do, and logs every change.
